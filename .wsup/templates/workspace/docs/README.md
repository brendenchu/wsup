# Documentation

Use this folder for durable workspace decisions and reference material. Keep
project-specific setup and decisions with the project that owns them. Prefer a
project's own `docs/` directory or another established location for its durable
documentation. Keep one canonical copy; link to it rather than maintaining
duplicates.

Use visible `workbench/` for human-authored drafts, temporary analysis, and
working notes when useful. Sanitized drafts are eligible for local Git tracking,
but review contents before staging; no commits happen automatically. Promote
approved knowledge into the owning project's maintained documentation. Keep
restricted records out of documentation and Git repositories.

Local session notes, plans, handoffs, and investigation evidence belong in
ignored `workbench/.local/`, created on demand. Ignoring files provides neither
backup nor confidentiality and does not make useful work disposable.

The workspace starter also creates standard project homes in `apps/`,
`packages/`, `tools/`, and `infrastructure/`, plus `docs/` and `workbench/`.
Learning, research, reference, and journal homes can be selected through the
optional collection CLI; they are not generated by default.

See [the workspace model](workspace-model.md) for registry fields, check
configuration, local settings, reports, and template updates.
