# Infer project conventions

Read the owner's guidance and tool configuration. Inspect representative files
across the requested scope, including counterexamples. Record the scope sampled;
a small sample does not establish a whole-workspace convention.

Separate deliberate house decisions from language/framework defaults, automated
formatting and individual anomalies. For each candidate, cite concrete source
examples and any conflicting patterns. Where practices differ by path or context,
propose scoped rules; do not turn a mixed practice into a universal requirement.

Record new rules only within the authorised scope. Label a proposed future
standard separately from an observed convention. Use a local rule index with a
precise task/path trigger and keep the rule self-contained in its owning project.
Avoid copying application identities, credentials, runtime versions or framework
requirements into portable defaults.

Completion means recorded conventions have evidence, meaningful scope and a
local discovery path, with conflicts and incomplete coverage stated plainly.
