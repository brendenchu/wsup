# Issues

Use one Markdown file per issue, named with a stable key such as `TEAM-123.md`.
Copy [TEMPLATE.md](TEMPLATE.md), replace the example fields, and keep the key
unique within this workspace. This is a file convention, not a tracker
integration or a replacement for a tracker your team already uses.

Use the status and priority values consistently. Update the issue when scope,
ownership, status, or acceptance criteria change. Link related issues by key,
and record a concise resolution before marking an issue done. Keep
implementation details and long-lived documentation with the owning project.

Issues are committed like other workspace files. Keep secrets and restricted
personal information out of them.
